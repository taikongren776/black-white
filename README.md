# 黑白棋：三种搜索算法完整程序

使用 Python 实现题目指定的**最小最大搜索、Alpha-Beta 剪枝搜索、蒙特卡洛树搜索**。提供中文图形界面、命令行对局和算法比较脚本，所有代码均可阅读和修改。

## 1. 运行方法

环境：**Python 3.10 或更高版本**，图形界面需要 Python 自带的 Tkinter。Windows 官方 Python 安装程序默认包含 Tcl/Tk。程序只使用标准库，**不需要安装第三方包**。

将压缩包解压到文件夹后，双击 `start.bat`，或在本目录打开终端运行：

```bash
python main.py
```

默认玩家执黑，Alpha-Beta 执白。下拉框可以分别给黑白双方选择“玩家”或三种算法，因此支持双人、人机以及任意两种算法互相对战。修改设置后点击“开始 / 重新开始”。

- 棋盘浅色圆点表示合法落点，金色点表示上一步落子。
- 深度 1—5 只控制最小最大搜索和 Alpha-Beta；默认 3。
- 模拟次数 10—10000 只控制 MCTS；默认每步 600 次。
- “暂停对局”可中止当前搜索，继续时重新搜索当前局面。
- 人机对战的“悔棋”回到玩家上一次落子机会；AI 对战悔棋后暂停，便于观察。
- 右侧显示棋谱、翻子数、搜索耗时和节点数；无需等待搜索完成就可以暂停、悔棋或重新开始。

最小最大搜索随深度增加较慢，建议先使用深度 3。MCTS 模拟次数越多通常越稳定，但并不保证每次都更强。

## 2. 题目规则对应

棋盘为 8×8；黑棋初始位于 E4、D5，白棋位于 D4、E5；黑方先行。合法落子必须在空格，并在横、竖或斜线的至少一个方向夹住一枚或多枚连续的对方棋子。八个方向所有被夹住的棋子都会翻转；空格会中断夹子。

有合法棋步就必须落子。某方无合法棋步时自动跳过；棋盘填满或双方均无合法棋步时结束，即使还存在空格。最后比较黑白棋子数，相同则平局。

## 3. 三种算法

### 3.1 最小最大搜索（Minimax）

实现位置：`reversi/search.py` 的 `minimax`、`_minimax`。

以当前根棋手为估值视角：自己的回合取子节点最大值，对手的回合取最小值。遍历给定落子深度内的全部合法分支，叶子采用统一估值函数。无棋可走时交换行棋方，**跳过回合不消耗落子深度**；终局采用真实胜负分数。

设平均分支数为 b、深度为 d，时间复杂度约为 O(b^d)，递归深度为 O(d)（夹杂跳过节点）。

### 3.2 Alpha-Beta 剪枝搜索

实现位置：`reversi/search.py` 的 `alphabeta`、`_alpha_beta`。

使用与 Minimax 相同的深度和估值。alpha 表示当前最大化方已知的下界，beta 表示最小化方已知的上界；当 alpha ≥ beta 时，后续分支不会改善当前决策，因此停止搜索该节点剩余分支。程序按位置权重优先搜索角等着法，以增加剪枝机会。

同一局面、相同深度下，两种算法应得到**相同的最优估值**；存在多个等值着法时，落子可能不同。最坏时间复杂度仍为 O(b^d)，理想着法顺序下可接近 O(b^(d/2))。

### 3.3 蒙特卡洛树搜索（MCTS）

实现位置：`reversi/search.py` 的 `mcts`、`_Node`、`_rollout`。

每次迭代依次执行：

1. **选择**：利用 UCT 走到尚可扩展的节点。
2. **扩展**：随机选择一个尚未尝试的合法动作，建立一个子节点；无合法落子但对手可下时，建立“跳过”节点。
3. **模拟**：双方均匀随机落子，直到终局。
4. **回传**：根棋手胜记 +1、负记 −1、平记 0，将结果回传到根。

节点保存根棋手视角的累计收益 W、访问次数 N。选择子节点 i 时：

```text
UCT(i) = s × Wi / Ni + c × sqrt(ln(Nparent) / Ni)
s = +1：当前节点轮到根棋手
s = −1：当前节点轮到对手
c = sqrt(2)
```

对手节点对平均收益取负，确保对手选择对根棋手不利的行动。所有迭代完成后，根节点选择**访问次数最多**的着法；次数相同时比较平均收益。MCTS 不调用前两种算法的启发式估值。

### 3.4 前两种算法共用的估值

非终局分数为：

```text
位置权重差 + 15 × 合法着法数差 − 5 × 前沿棋子数差 + 阶段权重 × 棋子数差
```

“差”均指己方减对方。角位置权重高，靠近空角的危险位置权重低；前沿棋子指与空格相邻的棋子。空格多于 16 时棋子数权重为 1，否则为 8。终局获胜得 `1000000 + 100 × 净胜子数`，失败为对应负分，平局为 0，保证真实胜负优先于非终局估值。

该估值是一种教学用启发式，并不意味着每个局面都能找到全局最优策略。

## 4. 命令行和重复实验

玩家执黑，对抗最小最大搜索：

```bash
python main.py --cli --white minimax --depth 3
```

Alpha-Beta 对抗 MCTS：

```bash
python main.py --cli --black alphabeta --white mcts --depth 3 --iterations 600 --seed 2026
```

在相同初始局面和固定随机种子生成的中盘局面上比较三种算法，并导出 CSV：

```bash
python compare.py --depth 3 --iterations 600 --seed 2026 --csv comparison.csv
```

搜索统计解释：Minimax 和 Alpha-Beta 的节点数为递归访问的节点数（包括叶子、跳过节点）；MCTS 的节点数为实际建立的树节点数（包括根），随机模拟经过的局面不计入该数。MCTS 的平均收益在 −1 到 1 之间，不能直接与前两种算法的估值比较。单步耗时也不等于棋力；比较胜率应进行多盘比赛、交换先后手并使用多个种子。

`--seed` 固定 MCTS 随机数以便复现实验；图形界面也接受上述棋手、深度、模拟次数和种子参数，省略 `--cli` 即可。
